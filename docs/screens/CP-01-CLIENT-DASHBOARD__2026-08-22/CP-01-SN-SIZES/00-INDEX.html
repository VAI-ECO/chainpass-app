CANON-CP-01 · the client dashboard — SN-33 to SN-41

The API is the product. The dashboard is a client of it. 9 screens × three sizes = 27 files, four stacked states each — 36 state frames. Provider-hosted and optional: the default front door for a platform that will never build its own, with no private endpoints and nothing it can do that the API cannot. Every surface is scoped to the key — a platform reads only its own — and a legal name, a document, a baseline and a percentage are never readable by any platform, on any endpoint or dashboard.

Drawn to the official breakpoints: phone below 768 is the default with no query, @media (min-width:768px) is tablet, @media (min-width:1024px) is computer. No fourth. The -T file is drawn at 768 — the low edge of the band, which is where a wide layout actually breaks — and every page carries width:min(100% - 32px, 1200px) so the gutter survives there. These are list surfaces and get their real wide treatment: tables run full width and scroll horizontally on the phone, KPI grids go two across at 768 and four across at 1024. Nothing uses the narrow flow column. SN-41 is a stub and stays empty. §14.6 names eight surfaces; the register numbering reserves a ninth and its subject is unruled, so nothing plausible is drawn into it — an unruled screen that looks ruled becomes a register row, and the register is what build reads.
